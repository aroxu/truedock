## 주요 기능

- **실시간 서버 개요:** 시스템 상태, 알림, CPU, 메모리, 네트워크 트래픽, 디스크 I/O, 가동 시간과 실행 중인 작업을 확인합니다.
- **스토리지 관리:** 풀, 디스크, 데이터셋, Zvol, 스냅샷, 할당량, 권한과 POSIX1E 또는 NFS4 ACL을 관리합니다.
- **데이터 보호:** 주기적 스냅샷, 복제, 클라우드 작업, Rsync와 풀 스크럽 일정을 구성합니다.
- **앱과 워크로드:** 카탈로그를 탐색하고 앱을 설치·재구성하며 서비스, 가상 머신과 지원되는 컨테이너를 제어합니다.
- **시스템 제어:** 계정, 네트워크, 공유, 업데이트, 부트 환경, 알림, 메일, Cronjob과 전원 작업을 관리합니다.
- **직접 연결과 보안:** TrueDock 계정이나 중계 서버 없이 WSS 기반 JSON-RPC 2.0으로 NAS에 직접 연결합니다.
- **보호된 인증정보:** Keychain 또는 Keystore, TrueDock PIN, 선택적 생체 인증 잠금 해제, OTP와 서버별 인증서 검증을 사용합니다.
- **모든 화면에 최적화:** Material Design 3, 라이트·다크 테마, 사용자 색상, 동적 글자 크기와 휴대전화·태블릿 적응형 탐색을 지원합니다.

현재 주요 지원 범위는 [주요 기능](#주요-기능)에서, 설치에 필요한 조건은 [설치](#설치)에서 확인할 수 있습니다.

## 왜 TrueDock인가요?

|  | TrueDock | 모바일의 TrueNAS 웹 화면 |
| --- | --- | --- |
| 인터페이스 | 터치 중심 네이티브 Material 3 UI | 전체 데스크톱 관리 UI |
| 연결 방식 | TrueNAS 서버에 직접 연결 | TrueNAS 서버에 직접 연결 |
| 모바일 보안 | PIN 보관함, 생체 인증, Keychain/Keystore | 브라우저의 인증정보 처리 |
| 여러 서버 | 저장된 프로필과 인증 기반 전환 | 분리된 브라우저 세션 |
| 장시간 작업 | 전역 실시간 작업 센터 | 웹 화면의 작업 피드백 |
| 위험 작업 | 결과를 명시하는 네이티브 확인 절차 | 웹 화면의 확인 절차 |

새로 추가되었거나 아직 지원하지 않는 서버 기능에는 TrueNAS 웹 화면이 공식 대안으로 남습니다. TrueDock은 사용할 수 없는 제어 기능을 동작하는 것처럼 표시하지 않고, 연결된 서버의 버전·메서드·권한을 확인합니다.

## 설치

TrueDock을 사용하려면 **TrueNAS SCALE Community Edition 25.10 이상**과 서버에 대한 안전한 HTTPS/WSS 연결이 필요합니다.

### Android

1. [최신 GitHub 릴리스](https://github.com/aroxu/truedock/releases/latest)를 엽니다.
2. 기기에 맞는 APK를 다운로드합니다. 현재 출시되는 Android 기기는 대부분 `arm64-v8a`를 사용합니다.
3. Android가 요청하면 브라우저 또는 파일 관리자의 외부 앱 설치를 허용한 뒤 APK를 설치합니다.

`.aab` 파일은 스토어 배포용이므로 기기에 직접 설치할 수 없습니다.

### iOS 및 iPadOS

1. 위 **Add to AltStore** 배지를 눌러 TrueDock 소스를 추가한 뒤 AltStore에서 TrueDock을 설치합니다.
2. 또는 [최신 GitHub 릴리스](https://github.com/aroxu/truedock/releases/latest)에서 `truedock.ipa`를 내려받아 호환되는 사이드로딩 도구로 설치합니다.

사용 가능한 기간과 갱신 제한은 사이드로딩 도구에서 사용하는 서명 방식 및 Apple 계정에 따라 달라집니다.

## 빠른 시작

1. TrueDock을 실행하고 TrueNAS HTTPS 주소를 입력합니다.
2. 서버 인증서의 신원과 SHA-256 지문을 확인합니다.
3. 사용자 이름과 비밀번호로 로그인하거나 API 키 인증을 선택합니다. 계정에 이중 인증이 설정되어 있으면 OTP 입력을 이어서 진행합니다.
4. 필요하면 **로그인 유지**, TrueDock PIN과 생체 인증 잠금 해제를 활성화합니다.
5. 적응형 탐색 메뉴에서 개요, 스토리지, 데이터 보호, 앱, 시스템 또는 앱 설정을 엽니다.

알 수 없는 인증서를 승인하거나 파괴적인 작업을 실행하기 전에 위 [빠른 시작](#빠른-시작)의 연결 절차를 확인해 주세요.

## 개인정보 보호

TrueDock은 사용자가 설정한 서버에 직접 연결합니다. 별도의 TrueDock 계정이나 중계 백엔드가 없습니다.

공식 빌드는 익명 충돌·오류·표본 성능 진단정보를 Sentry로 전송할 수 있으며 사용자가 수집을 거부할 수 있습니다. 진단정보에는 서버 주소, 리소스 및 계정 이름, 인증서, API 페이로드, 인증정보, 스크린샷과 서버의 원본 오류 내용이 포함되지 않습니다. **앱 설정 → 개인정보 보호**에서 즉시 수집을 끌 수 있으며, Sentry DSN이 없는 빌드는 아무 정보도 전송하지 않습니다.

수집하는 정보와 제외하는 정보는 위 [개인정보 보호](#개인정보-보호) 항목에서 확인할 수 있습니다.

## 소스에서 빌드하기

### 요구 사항

- 최신 안정 버전 [Flutter SDK](https://flutter.dev)
- iOS 빌드용 Xcode
- Android 빌드용 Android Studio 또는 Android SDK
- 실제 기능 테스트에 사용할 TrueNAS SCALE Community Edition 25.10 이상 서버

```bash
git clone https://github.com/aroxu/truedock.git
cd truedock
flutter pub get
flutter run
```

변경사항을 제출하기 전에 다음 명령을 실행하세요.

```bash
flutter analyze
flutter test
./tool/release_check.sh
```

서버 상태를 변경하는 테스트에는 폐기 가능한 TrueNAS 가상 머신을 사용하세요. 실제 서버 주소, 인증정보, API 키 또는 인증서를 소스 관리에 포함해서는 안 됩니다.

## 기여하기

TrueDock은 기여를 환영합니다. Pull Request를 열기 전에 다음 사항을 확인하세요.

1. 저장소의 `AGENTS.md`에 적힌 제품 범위, 아키텍처, 보안 규칙과 완료 기준을 읽습니다.
2. 변경 범위를 명확하게 유지하고 동작 변경에 대한 테스트를 추가합니다.
3. 위 검증 명령을 실행합니다.
4. 아키텍처, 보안 또는 제품 범위를 크게 바꾸는 제안은 먼저 [Issue](https://github.com/aroxu/truedock/issues/new/choose)로 논의합니다.

버그 제보에는 TrueNAS 버전, 관련 권한, 기대한 동작과 실제 동작을 적어주세요. 인증정보, 전체 서버 주소, 인증서 또는 기타 민감 정보가 포함된 제보는 별도 고지 없이 삭제될 수 있습니다.
