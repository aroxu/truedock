# Anonymous diagnostics

TrueDock official builds may send anonymous crash, error, and performance
diagnostics to Sentry. Collection is enabled by default, disclosed the first
time an official build runs, and can be disabled immediately or later under
App Settings > Privacy.

Open-source and local builds do not send diagnostics unless a maintainer adds a
DSN at build time. The Android and iOS release scripts load the public `dsn`
from the local, gitignored `sentry.properties`; direct Flutter commands can pass
it explicitly:

```sh
flutter build apk \
  --dart-define=TRUEDOCK_SENTRY_DSN=https://public-key@example.ingest.sentry.io/project \
  --dart-define=TRUEDOCK_SENTRY_ENVIRONMENT=production
```

For signed iOS releases, `tool/release_archive.sh` reads the gitignored
`sentry.properties` generated by the Sentry wizard. It uses the public `dsn`
for the runtime SDK and keeps `auth_token` confined to debug-symbol upload:

```sh
export TRUEDOCK_TEAM_ID=<Apple Developer team id>
./tool/release_archive.sh
```

CI may provide the equivalent `TRUEDOCK_SENTRY_DSN`, `SENTRY_AUTH_TOKEN`,
`SENTRY_ORG`, `SENTRY_PROJECT`, and `SENTRY_URL` environment variables.

The script gives Dart and native iOS events the same release and distribution,
then runs `sentry_dart_plugin` after the IPA is produced. A partial Sentry
configuration fails before signing rather than creating an unsymbolicated
official build. With all Sentry values absent, it intentionally produces a build
with diagnostics disabled and skips symbol upload.

The DSN is intentionally not committed. A Sentry DSN is a client routing value,
but keeping it in the official build configuration lets forks build without or
replace the service. Sentry management tokens and source-map upload credentials
are secrets and must never be passed through source-controlled files.

## Collected

- crash type and stack trace;
- Flutter and native error location with the error text removed;
- application version, operating-system version, device model class, and
  simulator status;
- sampled application-start, screen-load, slow-frame, frozen-frame, and frame
  timing information.

Performance traces use a 10% sample rate. Profiling, logs, analytics, user
interaction tracing, automatic sessions, feedback, screenshots, view hierarchy,
attachments, and Session Replay are disabled.

## Never collected

- TrueNAS addresses, host names, certificates, server names, or account names;
- dataset, pool, disk, share, application, task, or other resource names;
- API methods, parameters, responses, request bodies, headers, or breadcrumbs;
- passwords, PINs, API keys, sessions, one-time codes, or other credentials;
- screenshots, screen structure, free-form logs, or stable device identifiers.

Before an event leaves the process, TrueDock removes the user, request, server,
breadcrumb, tag, extra-data, response, feedback, and feature-flag fields. Error
messages are replaced with fixed redacted text. Diagnostic envelopes are not
persisted on the device.

Disabling collection closes the SDK immediately. The preference is local to the
device and is preserved across launches until all TrueDock device data is reset.
